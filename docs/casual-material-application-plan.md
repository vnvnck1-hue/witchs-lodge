# 마녀산장 — 캐주얼 재질 표현 적용 기획서

작성일: 2026-10-14 · 버전: 0.1 · 상태: **기획 작성 완료 / 이 기획에 따른 신규 에셋 수정은 미착수**

사용자 요청에 따라 지금은 적용 계획과 레퍼런스를 보존한다. 기존 게임에는 화면 스타일 7종이 적용되어 있으며, 이 문서의 텍스처·모델 수정은 다음 제작 단계다. 이번 작업에서는 게임 코드·모델·텍스처·배포 실행 데이터를 수정하지 않는다.

## 1. 목표와 범위

기존 마녀산장의 구도와 분위기를 유지하면서 작은 무늬를 줄이고, 적은 수의 크고 명확한 특징으로 재질을 설명한다. 카드 원화와 월드가 함께 보일 때 간결한 색면과 읽기 쉬운 형태가 이어지도록 한다.

사용자가 강조한 수정 폭은 **‘살짝’**이다. 카메라, 산장·목장·숲길의 배치, 프랍 수, 캐릭터 크기, 보라·인디고 설경, 앰버 창문과 등불을 유지한다. 재질 하나씩 비교하고, 형태 수정은 실루엣이나 표면 경계를 정리하는 데 필요한 부분에 한정한다.

첫 적용 대상은 **산장 목재 → 지붕 눈 → 바위**다. 이 세 대상에서 방향을 확인한 뒤 침엽수·생활 소품·양·캐릭터로 확장한다. 카드 UI와 게임 규칙의 구현은 이 기획의 범위에 포함하지 않는다.

## 4. 재질별 제작안

### 산장 목재 — 첫 번째 시범

본채의 굵은 기둥·보·문·처마에서 두툼한 인상을 유지한다. 주요 부재의 보이는 한 면에 큰 결 흐름 2~4개, 선택한 부재에 큰 옹이나 패임 0~1개를 시작 후보로 삼는다. 작은 옹이와 긁힘을 모든 판자에 반복하지 않는다.

결은 부재의 긴 방향으로 흐르고 잘린 끝에는 간단한 단면 패턴을 배치한다. 면마다 같은 무늬가 새로 시작되는 UV 반복을 줄인다. 넓은 밝은 면·기본색·제한된 접합부 음영으로 입체를 설명한다. 실제 광원과 중복될 강한 그림자를 색 텍스처에 넣지 않는다.

첫 비교는 텍스처와 UV만 수정한다. 부족한 곳에 한해 모서리의 둥근 정도나 패임을 조정한다. 건물 크기·문 위치·기단·교차 목재 장식의 기본 형태를 유지한다. 본채 확인 후 증축·울타리·통·장작에 확장한다.

### 지붕과 지면의 눈 — 큰 덩어리와 여백

라벤더 색과 두툼한 처마 실루엣을 유지한다. 지붕 내부의 작은 눈 조각 경계를 줄이고 둥근 처마 덮개·능선의 눈·드문 큰 갈라짐이 읽히게 한다. 지붕 양쪽 면을 넓게 연결한 후보와 현재 조각 수를 줄인 후보를 같은 구도로 비교한다. 전체 지붕을 다른 형태로 다시 디자인하지 않는다.

눈 표면은 넓은 밝은 영역과 부드러운 푸른 보조색으로 정리한다. 작은 반점과 촘촘한 눈 결정 묘사를 줄인다. 해상도와 가장자리 선명도를 유지하면서 무늬 빈도를 낮추고, 이미지 전체를 흐리는 방식은 사용하지 않는다.

지면은 별도 작업이다. 길의 흐름, 산장 앞 따뜻한 빛, 숲 가장자리의 보라·청록 어둠을 보존하고 공터의 잔붓질과 작은 얼룩만 줄인다. 텍스처에 포함된 붓질과 셰이더가 더하는 색·빛을 따로 확인한다.

### 바위 — 큰 면과 드문 깨짐

주암·부암의 배치, 높이 차이, 눈 덮개를 유지한다. 큰 바위 덩어리당 특징적인 깨짐이나 끊어진 균열 1~2개를 시작 후보로 삼는다. 큰 면이 만나는 읽히는 위치에 특징을 집중하고 뒤쪽·아래쪽은 조용하게 둔다.

잔돌 무늬와 작은 면 경계를 줄이되 완전히 둥근 구로 만들지 않는다. 돌의 큰 면과 눈의 부드러운 가장자리가 구분되어야 한다.

### 침엽수·생활 소품 — 반복 밀도 조절

나무 수와 현재 층 구조를 유지한다. 연결된 가지 덩어리를 바탕으로 잎 무늬와 잔톱니 반복을 줄인다. 눈은 가지의 높이 곡선을 따라 넓게 덮고, 뭉친 원뿔로 보이지 않도록 큰 층과 틈을 남긴다. 잎의 짙은 초록·청록이 보라 설경 속에서 은은하게 읽혀야 한다.

통의 세로 결, 장작 단면, 건초의 큰 묶음처럼 소품마다 한 가지 특징을 우선한다. 멀리서 안 보이는 작은 못·긁힘·줄 무늬를 추가하지 않는다. 큰 소품과 작은 소품에 같은 수의 무늬를 넣지 않는다.

### 양·캐릭터 — 환경 확인 후 확장

양은 둥근 양털 덩어리와 어두운 얼굴·발의 대비를 유지하고 털 한 올씩의 무늬와 작은 요철을 줄인다. 눈과 같은 흰 덩어리로 섞이지 않도록 외곽과 얼굴을 실제 화면에서 확인한다.

마녀·여행자는 옷의 큰 주름과 색 덩어리, 모자·지팡이·배낭처럼 식별 특징을 남긴다. 괴물·용은 뿔·잎 외피·날개막·큰 비늘 중 대표 특징을 정리한다. 카드 초상과 연결되는 색·도구·실루엣을 유지하고 등신·애니메이션·장비 앵커는 유지한다.

## 5. 셰이딩 프리셋과의 관계

캐주얼 재질의 기준은 깨끗한 표면과 읽히는 형태다. 조명의 단계 수와 외곽선 강도는 기존 프리셋에서 별도로 비교한다. 레퍼런스의 부드러운 조명을 근거로 기존 강한 툰을 없애거나 모든 프리셋을 같은 강도로 바꾸지 않는다.

| 비교 프리셋 | 확인할 내용 |
| --- | --- |
| 부드러운 명암 — 주 제작 기준 | 기존 장면과 자연스럽게 이어지고 무늬를 줄여도 재질이 식별되는가 |
| 따뜻한 산장 / 차가운 숲 | 다른 빛에서도 같은 재질의 색·형태를 유지하는가 |
| 툰 셰이딩 | 단계 명암이 큰 면을 설명하고 과도한 얼룩을 만들지 않는가 |
| 강렬한 툰 셰이딩 | 깊은 그림자 속에서도 목재·돌·양·괴물을 구분하는가 |
| 두꺼운 툰 외곽선 | 실루엣은 또렷하고 내부 잔경계가 선 덩어리로 뭉치지 않는가 |
| 기존 화면 | 새 재질의 효과와 툰 조명의 효과를 분리할 수 있는가 |

재질 비교 중에는 프리셋 수치를 고정한다. 표면이 밋밋하면 큰 특징을 보완하고, 그림자가 너무 어두우면 조명·보조광을 별도로 비교한다. 내부 선이 과하면 메시 접합·법선·무늬 중 원인을 찾은 뒤 외곽선 임계값 조정을 검토한다. 모든 물체의 선을 일괄 약하게 만들어 해결하지 않는다.

### 구현 대상과 보존 조건

- 텍스처: `material_atlas.png`, 개별 GLB 아틀라스, `character_atlas.png`, `ground_cleanplate.png`. 공용 원본과 에셋별 출력의 관계를 확인하고 시범 대상에만 새 후보를 연결한다. 기존 UV 구획과 테두리 여유를 보존한다.
- 모델·UV: [환경 생성 스크립트](../godot/art_sources/build_painted_assets.py), [캐릭터 생성 스크립트](../godot/art_sources/build_character_assets.py), Blender 원본과 GLB. 기존 스크립트는 여러 에셋을 재생성하므로 별도 출력 폴더와 대상별 내보내기를 준비한다. 수정 대상 밖의 에셋을 재생성 결과로 덮지 않는다.
- 런타임 재질: `painted_models.gd`, `painted_prop.gdshader`, `painted_snow.gdshader`, `painted_ground.gdshader`, `stylized.gdshader`. 혼합량 감소와 새로운 패턴 제작을 구분하며 목재·눈·잎·양털에 같은 강도를 일괄 적용하지 않는다.
- 모델 교체: Y 위·정면 +Z·바닥 피벗, 에셋 경로·필요한 노드명·재질명, 캐릭터 분리 파트·앵커를 유지한다. 기존 충돌·내비게이션·공격 지점이 달라지지 않게 한다.
- 카드·HUD: 월드의 조명·재질 수정이 UI 색이나 입력을 바꾸지 않게 한다. 큰 카드가 올라오는 합성 시안을 보조 참고로 쓰되 현재 카드 런타임이 구현된 것으로 간주하지 않는다.

## 7. 비교 조건과 완료 기준

카메라·배치·프리셋·캡처 시점·UI 표시 여부를 맞춰 전후를 비교한다. 처음에는 부드러운 명암에서 텍스처만 바꾸고, 이후 필요한 모델 수정과 프리셋 비교를 진행한다. 한 장의 합성 원화나 확대 프랍만으로 전체 게임 적용 완료를 판단하지 않는다.

| 검증 항목 | 완료 판단 |
| --- | --- |
| 화면 정체성 | 산장·목장·숲길 위치와 기존 보라 설경을 바로 알아볼 수 있음 |
| 무늬 정리 | 잔무늬가 줄고 큰 특징으로 목재·돌·눈·양털을 구분함 |
| 형태 설명 | 결이 부재 방향을 따르고 돌의 큰 면·눈 덮개·잎 층이 읽힘 |
| 작은 화면 | 기존 1600×800 화면과 1280×720 창에서 주요 프랍·캐릭터가 식별됨 |
| 외곽선 | 큰 실루엣을 강조하고 눈 조각·판자·양털 내부 선이 불필요하게 뭉치지 않음 |
| 프리셋 | 7종·F2·일시 정지 중 전환, 같은 실행 내 새 게임의 선택 유지가 정상 |
| 게임 동작 | 방문·증축·전투·용 소환·피격·애니메이션 정상. 충돌·이동·경제 규칙 유지 |
| 성능·배포 | 같은 환경·장면의 전후 프레임 시간과 메시·메모리 변화를 기록하고 최종 실행파일에서 새 에셋 확인 |
| 근거 보존 | 실제 렌더 전후·수정 파일·남은 차이·검증 결과를 기록하며 이전 데이터를 복구 가능 |

기존 `verify_screen_styles.gd`는 프리셋 전환과 렌더 차이를 확인하는 도구다. 새 무늬의 품질·모델 접합·성능까지 증명하는 검증으로 사용하지 않는다. 실제 적용 완료는 위 기준의 추가 비교와 배포 확인이 끝난 뒤 별도로 기록한다.

## 8. 이번 기획 작성의 완료 상태

- 적용 방향·대상·순서·기존 프리셋과의 관계·검증 기준을 문서화했다.
- 첨부 레퍼런스를 프로젝트에 원본 그대로 보존하고 본문에 포함했다.
- 텍스처·모델 수정과 새 배포는 후속 작업이다. 현재 실행판은 기존 7종 프리셋 적용 상태다.
