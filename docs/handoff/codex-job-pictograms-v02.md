# Codex에게 요청하는 에셋 작업 — 용병 직업 픽토그램 v02 (작게 봐도 구별되는 타이트한 형태)

요청자: Claude (게임 구현 담당) · 2026-10-19 · 이전 납품: [v01 요청서·납품 결과](codex-job-pictograms-v01.md) · 기획: [장착 장비 · 용병 초상 메달](../equipment-and-party-frames-v01.md) §2

## 왜 다시 하나 (사용자 피드백 2026-10-19)

> "별로야. 이걸 사용하는 곳이 면적이 작으니까, 쉐입을 더욱 타이트하게 구성해야 될 거 같아. 작게 봐도 잘 구별되도록."

v01은 128px에서는 예쁘지만 **실제 게임에서 약 20px**로 줄면 뭉개진다. 원인:

- **물건이 둘 이상**(검+방패, 활+화살, 바구니+버섯+잎) → 작은 면적에서 서로 섞인다.
- **가는 선·내부 디테일**(활시위, 바구니 엮음, 방패 나뭇결) → 20px에서 사라지거나 얼룩이 된다.
- **대각선으로 길쭉한 형태**(활·도끼 자루) → 면적 대부분이 투명이라 작게 보이면 점처럼 보인다.

참고: 실제 게임 화면 4배 확대 `godot/screenshots/party-frames/job-badges-v01-ingame-x4.png`, v01 시트 `godot/screenshots/party-frames/job-pictograms-sheet.png`.

## 디자인 원칙 (v01과 달라지는 점)

1. **물건 하나, 실루엣 하나.** 한 직업 = 한 개의 덩어리. 겹치는 두 번째 물건 금지.
2. **캔버스를 꽉 채운다.** 투명 여백은 사방 **4px 이하**, 그림의 경계 상자가 최소 **116×116**. 길쭉한 물건은 굵기를 키워 면적을 채운다(가로세로 비율이 1:1에 가까운 덩어리).
3. **16×16 격자에서 먼저 설계**한다고 생각하고 그 형태를 128로 키운다. 16px로 줄였을 때 형태가 남지 않는 요소는 넣지 않는다.
4. **굵은 먹선 외곽 10~12px**(128 기준), 내부 선은 최대 1개(굵기 8px 이상). 질감·나뭇결·엮음·그라데이션·하이라이트 점 금지.
5. **큰 색면 2~3개:** 크림 본체 `#FCE7B0` + 먹선 `#2A1A12` + 강조색 1개(아래 표). 강조색 면도 크고 단순하게.
6. 네 형태의 **바깥 윤곽 자체가 서로 달라야** 한다(색을 빼고 실루엣만 보여도 구별).

생성은 내장 이미지 생성(참고 입력은 호출당 5장 이하: v01 시트, 게임 화면 4배 확대, v01 해당 직업 PNG 정도)으로 하되, **최종 형태 정리는 후처리에서 직접 다듬어도 좋다**(외곽 굵기 통일, 여백 축소, 불필요한 디테일 제거, 색 단순화). 납품 후 `.tools/Godot-4.7.2.exe --headless --path godot --import` 를 실행한다. 실행파일은 내보내지 않는다.

## 완료 기준

1. 4개 파일이 경로·규격(RGBA 128×128, 투명, 경계 상자 ≥116×116)대로 존재.
2. 시트의 **16px·20px에서 네 직업이 바로 구별**되고, **실루엣만으로도** 구별된다(직접 열어 확인).
3. 물건 하나·굵은 외곽·큰 색면 2~3개의 한 벌.
4. `--import` 종료 코드 0, 검증 JSON `passed=true`.
5. 이 문서 끝에 `## Codex 납품 결과 · <날짜>` 절(파일 목록, 재생성·수작업 보정 내용, 남은 문제)을 붙이고 마지막 메시지에 같은 요약.


## Codex 납품 결과 · 2026-10-19

- **완료:** 전투용병·사냥꾼·나무꾼·채집가 4종을 내장 이미지 생성으로 각각 재제작한 뒤 같은 게임 경로에 덮어썼다. 참고 이미지는 호출당 3장(총 4회)으로 제한했다.
- **교체 파일:** [warrior.png](../../godot/assets/ui/jobs/warrior.png), [hunter.png](../../godot/assets/ui/jobs/hunter.png), [lumberjack.png](../../godot/assets/ui/jobs/lumberjack.png), [gatherer.png](../../godot/assets/ui/jobs/gatherer.png).
- **제작 원본·사본:** [v02 폴더](../../art/ui/job-pictograms-v02/)에 직업별 `*-generated.png` 생성 원본 4개와 최종 `*.png` 사본 4개, 재현 가능한 후처리·검증·시트 생성 스크립트 `prepare-delivery.ps1`을 저장했다. `drafts/{직업}.png`는 교체 직전 v01 게임 PNG 사본이며 기존 v01 보관 폴더도 유지했다.
- **수작업 보정:** 생성 원본을 바탕으로 외곽을 직접 정리했다. 검 손잡이의 잔선을 제거하고 십자 가드를 넓혔으며, 활은 굵은 D자·수직 시위·오른쪽 화살촉을 연결했다. 도끼는 반달 머리를 위쪽으로 압축하고 굵은 짧은 자루를 붙였고, 버섯은 점 없는 큰 갓과 짧은 기둥만 남겼다. 외곽은 최종 약 10px로 통일하고 큰 색면 3개와 경계 안티앨리어싱을 사용했다. [실제 프롬프트·보정 기록](../prompts/ui/job-pictograms-v02-prompts.md).
- **직접 시각 검수:** [미리보기 시트](../../godot/screenshots/party-frames/job-pictograms-v02-sheet.png)의 128px 원본, 직업 배지색을 35% 어둡게 한 원 위의 실제 16·20·24px 축소본, 검정 20px 실루엣, v01/v02 20px 비교와 4배 확대를 열어 확인했다. 작은 크기에서도 뾰족한 십자 검 / D자와 화살촉 / 비대칭 반달 도끼 / 둥근 버섯이 구별된다.
- **규격 검증:** 모두 RGBA 128×128, 모서리 알파 0, 사방 투명 여백 4px, 비투명·완전 불투명 경계 상자 모두 120×120, 연결 실루엣 1개다. SHA-256과 파일별 검증을 [verification.json](../../output/job-pictograms-v02/verification.json)에 기록했으며 최종 `passed=true`다.
- **Godot 임포트:** 지정한 `--headless --path godot --import`를 실행해 종료 코드 **0**을 확인했다. 4개 임포트 캐시의 원본 MD5가 최종 PNG와 일치한다. [표준 출력](../../output/job-pictograms-v02/godot-import.log) · [표준 오류](../../output/job-pictograms-v02/godot-import-errors.log).
- **남은 문제·범위:** 에셋 규격상 미해결 문제는 없다. 제한된 실행 환경에서 시스템 루트 인증서 저장소를 읽지 못했다는 진단 1건이 남았으나 임포트는 성공했고 캐시 일치도 확인했다. 에디터 설정 쓰기 경로는 해당 프로세스의 `APPDATA`를 작업 폴더 안으로 돌려 해결했다. 실제 게임 화면 확인과 실행파일 내보내기는 요청서의 역할 분담에 따라 Claude 담당으로 남긴다. 수정 금지 소스·다른 UI 자산·루트 실행파일을 직접 수정하지 않았고, 커밋하지 않았다.
