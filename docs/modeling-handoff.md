# 마녀산장 — 모델링·Godot 에셋 인수인계

**산장 주변 배치 후속 기준(2026-10-17):** [승인 A안 맵 구성 인수인계](handoff/lodge-map-layout-a-v01.md)를 함께 확인한다. 산장 뒤는 자연물로 통행을 차단하고 증축 여유는 왼쪽 측벽에 연결한다. 이 지역의 배치·후면 통행·증축 방향은 아래 초기 배치와 측면/후면 증축 제안보다 최신 A안을 우선한다. 공통 에셋 축·피벗·납품 규격은 계속 참고한다.

작성일: 2026-10-13. 이 문서는 **중앙의 작은 산장 + 옆의 작은 양 목장 + SD 플레이어** 시작 장면을 3D로 만드는 제작 기준이다. [게임 규칙·밸런스 인수인계](godot-prototype-handoff.md)와 함께 사용한다.

**카드 전환 후 안내:** 월드 에셋 기준은 유지하며 다음 게임플레이는 [카드 코어 v0.3](kingdom-integration-design.md)을 따른다. 용병의 초상/소환/작업/귀가, 양 수확 상태, 아군 몬스터 구분과 하단 손패 가림을 추가 검토한다. 아래 ‘공물은 UI 버튼’, 기존 애니메이션·추가 모델 목록은 최초 프로토타입 범위이며 카드판 전체 납품 목록이 아니다. 카드용 신규 아트·애니메이션은 아직 납품하지 않았다.

## 1. 자료의 우선순위와 현재 상태

1. [프로토타입 승인 기준](../art/concepts/environment/04-prototype-reference-simplified.png): 높은 카메라, 공간 배치, 작은 본채 규모, 옆 목장, 적은 프랍과 간결한 텍스처. 2026-10-13 사용자 승인.
2. [새 산장 3면도와 리모델링 기준](lodge-redesign.md): 작은 본채의 곡선 처마·굵은 목재·낮고 통통한 비례를 새로 설계했다. 산장 재모델링은 이 시트를 우선하며 실제 Blender 모델과 게임 적용은 진행 중이다.
3. [기존 12종 시트](../art/model-sheets/starter/README.md): 다른 개별 에셋의 구조·축·피벗 참고. 앞·오른쪽·뒤, 바닥은 앞·오른쪽·위. 기존 산장 시트는 보존하며 새 산장 설계와 충돌하는 부분은 새 시트를 우선한다.
4. [현재 아트 방향](art-direction.md): 약간 과장한 프랍 형태, 큰 색면과 넓은 명암, 퍼플 설경, 짙은 초록 나무, 따뜻한 빛.
5. [방문·증축·괴물·용 원화](../art/README.md): 확장 장면의 연출 방향.

이전 [높은 복합 산장 시트](../art/model-sheets/witch-lodge-front-right-back.png)는 초기 탐색 자료다. 최신 작은 본채의 설계로 쓰지 않는다.

현재 제공물은 PNG 원화와 Markdown·JSON 기록, Godot 장면, 편집용 `.blend`와 13개 `.glb`다. [실제 모델과 원화 비교 기록](art-refinement-progress.md)을 먼저 확인한다. 캐릭터 애니메이션은 코드 기반이며 본 리깅 납품은 아니다. 생성 시트의 보이지 않는 면은 추정했으며, 면 사이의 미세한 차이를 그대로 복제하기보다 정면 실루엣과 기준 장면을 우선한다. 시트 간 픽셀 크기는 절대 축척이 아니다.

![프로토타입 승인 기준 장면](../art/concepts/environment/04-prototype-reference-simplified.png)

기존 `model-sheets/starter/scene-reference.png`는 12종 시트 제작 당시의 배치 참고로 보존한다. 시트와 최신 승인 이미지가 충돌할 때 카메라·밀도·텍스처 표현은 최신 이미지를 우선한다.

## 2. 공통 제작 규격 — 블록아웃 제안

### 좌표·축척·원점

- Godot 기준 **1단위 = 1m**, Y 위쪽, 모델의 얼굴·문이 향하는 정면은 +Z로 통일한다. 에셋 루트의 위치/회전은 0, 스케일은 1로 납품한다.
- 캐릭터는 발바닥 중앙, 바닥 프랍은 바닥 접점 중앙, 건물은 기단 바닥 중앙을 원점으로 둔다. 회전하는 문은 힌지에 별도 피벗을 둔다.
- Godot의 카메라 전방은 -Z지만 방향성 모델의 권장 정면은 +Z이다. 이동 코드와 모델 방향이 어긋나면 `VisualRoot`에서 보정하고 프랍마다 제각각 축을 바꾸지 않는다. [공식 모델 내보내기 고려사항](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/model_export_considerations.html)

| 에셋 | 제안 블록아웃 크기 | 화면에서의 판단 기준 |
| --- | --- | --- |
| 마녀 | 모자 포함 높이 약 1.2m | 2~3등신, 작은 몸과 큰 머리. 건물보다 인물이 커 보이지 않음 |
| 본채 | 폭 5.5m × 깊이 4.5m, 지붕 꼭대기 약 4.8m | 작은 한 덩어리 집, 단일 박공지붕 |
| 문 | 높이 약 1.5m × 폭 0.9m | 마녀가 드나들 크기, 실루엣 판독 가능 |
| 침엽수 | 높이 4~8m 변형 | 나무 사이에 눈밭과 경로가 보이는 간격 확보, 앞쪽 가림 제한 |
| 양 | 등 높이 약 0.55m, 길이 약 0.9m | 플레이어보다 낮고 통통함 |
| 울타리 | 구간 길이 1.3m, 높이 0.7m | 낮고 단순한 반복 구간 |
| 목장 | 약 4m × 3m | 본채 옆의 작은 부속 영역, 양 3마리가 보임 |
| 용 | 펼친 전체 폭 약 10~12m | 지붕과 사람보다 압도적. 아래 플레이 구역은 읽혀야 함 |

이 치수는 생성 이미지에서 측정한 값이 아니라 조립 시작값이다. 본채·마녀·양·울타리를 함께 세워 승인한 뒤 확정한다. 모자를 키운다고 캐릭터 몸 전체를 늘리지 않는다.

### 모델·재질·파일

- 큰 면과 간단한 실루엣으로 만든다. 눈 덮개, 목재, 돌, 잎, 천은 색과 큰 형태로 구분한다. 실사 표면·미세 거칠기·작은 장식 밀도를 낮춘다.
- 두꺼운 모서리와 약간 과장한 프랍 비율을 사용하되, 텍스처는 큰 색면·넓은 명암·절제된 붓질로 단순화한다. 잔균열·촘촘한 나뭇결·눈밭의 작은 색조각을 추가하지 않는다. 화면을 흐리게 하거나 텍스처 해상도를 무조건 낮추는 방식으로 대체하지 않는다.
- 짙은 초록 잎을 눈 아래 남긴다. 눈은 라벤더·페리윙클, 어두운 면은 인디고·보라로 읽히게 한다. 시트의 스튜디오 배경·그림자는 모델이나 텍스처에 굽지 않는다.
- 창문·등의 발광 면을 따로 식별할 수 있게 만든다. 실제 조명은 Godot에서 배치한다. 바닥 전체에 주황빛을 굽지 않는다.
- 기본 납품은 편집 가능한 `.blend`와 **glTF 2.0 `.glb`**. 정적 에셋은 에셋별, 캐릭터는 리그·애니메이션을 포함한 단위로 내보낸다. PNG 텍스처 사용 시 같이 전달한다.
- 내보내기 전 변환 적용, 노멀·뒤집힌 면·중복 정점 확인, 삼각화 결과 확인, 리그 휴식 자세 확인을 수행한다. Godot에서 그림자와 크기를 재검증한다.

Godot는 glTF 2.0/GLB를 지원한다. `.blend` 직접 가져오기는 Blender 설치에 의존하므로 인수인계의 실행용 파일은 GLB로 제공한다. [지원 형식 공식 문서](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html)

처음에는 작은 단색 팔레트와 재질 공유를 우선한다. 텍스처 해상도·폴리곤 상한·LOD는 성능 측정 후 정한다. 아직 폴리곤 예산이 승인된 상태는 아니다.

목장 문은 초기 프로토타입에서 항상 열린 상태로 조립한다. 양은 목장 배회 범위로 제한하고, 몬스터는 문을 통해 들어와 양에 접근한다. 닫힌 문을 공격·파괴하는 시스템은 첫 범위에 추가하지 않는다. 시트는 닫힌 외형을 보여주므로 피벗 분리가 필요하다.

울타리 기둥·가로대를 분리해 납품하면 모서리 중복을 줄일 수 있다. 완성 구간 메시를 같이 제공해 반복 배치가 쉽게 한다.

## 4. 본채와 증축을 위한 앵커

본채 자체를 증축 때마다 새 모델로 교체하지 않는다. 최초 본채는 유지하고 객실 모듈을 붙인다. 목장과 두 숲길을 침범하지 않는 측면/후면에 객실을 붙일 자리를 블록아웃 때 확보한다.

| 제안 앵커·소켓 | 목적 |
| --- | --- |
| `EntranceAnchor` | 손님의 입실·퇴실 표현, 문 앞 도착 위치 |
| `AttackPoint_*` | 적이 건물 밖에서 공격할 수 있는 여러 지점 |
| `ExtensionAnchor` | 객실 1종의 바닥·벽 연결 기준. 목장 반대쪽 공간 우선 |
| `DragonAnchor` | 본채 지붕 능선 위 용의 발 접점. 증축 여부와 관계없이 유지 |
| `ChimneySmokeAnchor` | 굴뚝 연기 시작점 |
| `LanternAnchor` | 벽등과 Godot 조명 배치 위치 |
| `WindowLightAnchor_*` | 창문 빛 배치 위치 |
| `StaffGrip` | 마녀 손과 지팡이 연결 |
| `GateHinge` | 목장 문짝 회전 기준 |

용은 시각적으로 지붕에 앉지만 물리 충돌로 지붕을 누르거나 플레이어를 막지 않는다. 지붕 파괴·물리 건축은 요구사항이 아니다. 몸과 꼬리는 일부 화면 밖으로 나가도 불덩이와 양·마녀의 위치는 읽혀야 한다.

| 거대한 용 | [용 원화](../art/concepts/gameplay/04-dragon-gold-defense.png), 3면도·리그 미제작. 지붕 발 접점, 발사 입 위치, 날개·꼬리 가림 우선 검토 |
| 불덩이·폭발 | 별도 프랍 시트 없음. 구형 메시와 파티클/재질로 먼저 구현 |

골드 상자·떠오르는 동전·공사 골조·수레는 필수 기능 에셋이 아니다. 공물은 우선 UI 버튼으로 표현한다. 원화를 완전히 재현하려고 첫 시연 제작을 막지 않는다.

## 6. 리그·애니메이션·VFX 최소 목록

| 대상 | 첫 구현에 필요한 동작 |
| --- | --- |
| 마녀 | idle, walk, 짧은 cast, hit, death. 이동 중 cast는 상체 또는 단순 효과로 표현 |
| 양 | idle, walk, hit, death. 사망 후 인스턴스 제거는 게임 코드 책임 |
| 여행자 | walk, idle. 입실 후 숨김, 퇴실 시 표시 |
| 몬스터 | walk, attack, hit, death |
| 용 | summon/착지, idle, 단발 fireball 발사, dismiss. 첫 기능 검증은 정적 모델+효과도 가능 |

첫 버전은 이동 코드가 실제 이동을 담당하고 애니메이션은 제자리 재생한다. 루트 모션에 경로 이동을 맡기지 않는다. 애니메이션 이벤트나 모델 교체로 피해를 두 번 적용하지 않게 한다.

눈 내림, 굴뚝 연기, 창문 빛, 작은 등불, 발자국, 용 등장 효과, 불덩이와 폭발은 Godot의 파티클·광원·재질·데칼로 구성한다. 이를 개별 정적 3면도 모델 목록에 억지로 추가할 필요는 없다.

## 7. Godot 납품 폴더 제안

```text
assets/models/environment/starter_lodge.glb
assets/models/environment/snow_pine.glb
assets/models/environment/fence_bay.glb
assets/models/environment/pasture_gate.glb
assets/models/environment/hay_pile.glb
assets/models/environment/snow_shrub.glb
assets/models/environment/snow_stone.glb
assets/models/environment/snow_ground.glb
assets/models/environment/wall_lantern.glb
assets/models/characters/witch_player.glb
assets/models/characters/sheep.glb
assets/models/props/crook_staff.glb
assets/materials/
assets/textures/
scenes/environment/  # 모델 래퍼: 충돌·소켓·조명
scenes/actors/       # 모델 래퍼: 이동·체력·행동
art_sources/         # 편집 가능한 원본과 모델별 제작 메모
```

아직 만들어진 경로가 아니라 제작자가 사용할 구조 제안이다. 원화는 저장소의 `art/`에 보관한다. `.glb` 가져오기 결과에 게임 스크립트와 충돌을 직접 덮어쓰기보다 래퍼 장면에서 연결한다. [Godot 가져오기 설정 공식 문서](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/import_configuration.html)

각 모델의 제작 메모에는 파일명, 크기, 정면 축, 원점, 재질, 애니메이션 이름, 소켓 위치, 원화에서 변경한 부분을 기록한다. 원본 모델과 GLB가 같은 버전인지 확인한다.

## 8. 모델 수락 기준

- 본채·플레이어·목장·양을 같은 장면에 배치했을 때 기준 그림과 비슷한 상대 크기다. 본채는 작은 단일 구조이며 화면 중앙에 있다.
- 승인 이미지와 같은 화면 크기로 비교해 높은 카메라, 넓은 빈 눈밭, 적은 장식 프랍과 낮은 표면 무늬 밀도가 유지되는지 확인한다. 기존 시트의 상세 묘사를 그대로 복제해 전체 화면을 복잡하게 만들지 않는다.
- 전체 화면은 퍼플 분위기이고 나무의 초록도 읽힌다. 창문과 등불의 따뜻함이 작지만 분명하다.
- 모델 루트 스케일 1, 바닥 접점 Y=0, 정면 축이 동일하다. 원점 이동으로 프랍이 땅에 파묻히지 않는다.
- 열린 목장 문을 통해 몬스터가 양에게 도달하고, 마녀도 공터와 문 앞을 이동할 수 있다.
- 울타리 모서리에서 기둥이 겹치거나 틈이 생기지 않는다. 양의 배회 범위가 목장 밖으로 새지 않는다.
- 본채 벽등을 두 번 배치하지 않는다. 창문·발광부의 재질 슬롯을 식별할 수 있다.
- GLB를 Godot에 가져왔을 때 재질 누락·반전 노멀·원하지 않는 크기 변화가 없다. 리그는 휴식 자세와 walk/cast를 확인한다.
- 실제 쿼터뷰에서 나무·용·지붕이 플레이어와 공격 경로를 과하게 가리지 않는다.
- 눈·연기·불덩이 효과를 꺼도 모델 자체의 실루엣이 읽힌다. 모델에 원화 배경을 포함하지 않는다.
